Rate-limiting

Le rate-limiting consiste à restreindre le nombre de requêtes qu'un client peut effectuer sur une période donnée.

On utilise son IP, son JWT ou sa clé d'API pour l'isoler.

Exemple: Middleware de rate-limiting

const rateLimit = require('express-rate-limit')

const limiteConnexion = rateLimit({
    windowMs: 60 * 1000,
    max: 5,
    message: { error: "Trop de tentatives de connexion." }
})

app.post('/login', limiteConnexion, (req, res) => {
    res.json({ success: true })
})

Caching

Le caching consiste à sauvegarder temporairement une copie des données fréquemment utilisées dans un espace de stockage très rapide (ex: RAM).

Exemples typiques:

  • Résultats de requêtes SQL complexes
  • Réponses d'API tierces
  • Données qui changent peu

Exemple: Caching avec Redis

const { createClient } = require('redis')
const redis = createClient()
await redis.connect()

function getUser(id) {
    const cache_key = "user"+id
    
    const cached = await redis.get(cache_key)

Frameworks multiclients

Permet de créer des applications pour plusieurs types de clients à partir d'une base de code unique.

Quelques exemples:

  • Flutter (Dart)
  • React Native (Typescript)
  • .NET MAUI (C#)
  • Ionic (HTML, CSS, JS)

Frameworks multiclients

Positifs

  • Code partagé
  • Mises à jour simplifiées
  • Synchronisation des fonctionnalités
  • Équipe multidisciplinaire

Négatifs

  • Performances non optimales
  • Limite des fonctionnalités
  • Comportements non natifs
  • Code natif parfois nécessaire quand même
